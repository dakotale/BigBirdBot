(confirmed as a known unresolved pgloader limitation for MSSQL sources: github.com/dimitri/pgloader/issues/1343).
This also cascaded into 1 failed foreign key (PetJournal->Pet) and left the affected tables'
identity sequences unset.

Remediation performed:
1. Extracted full column metadata for all 57 tables directly from sys.columns/sys.types/
   sys.identity_columns/sys.default_constraints (saved to backups/source-schema-columns.csv).
2. Generated corrected CREATE TABLE DDL for the 30 missing tables (backups/create-missing-tables.sql),
   translating getutcdate()/sysutcdatetime() defaults to `(now() AT TIME ZONE 'utc')` (or cast to
   ::date for the one date-typed column), and recreating identity columns as sequence-backed integer/
   bigint columns matching pgloader's own naming convention ("Table_Column_seq").
3. Discovered a SEPARATE pgloader inconsistency: 10 of the 27 originally-successful tables
   (AuditLog, Birthday, BotAIMessage, ChatKeyword, Music, MusicQueue, PlayerConnected, Pronouns,
   Servers, Words) have a genuine IDENTITY column in SQL Server (confirmed via sys.identity_columns)
   but pgloader created them with no sequence/default at all. Backfilled sequences for these 10
   (backups/fix-missing-sequences.sql) so future inserts work correctly.
4. Copied data for the 30 rebuilt tables directly from SQL Server to Postgres via a small
   Npgsql/Microsoft.Data.SqlClient console app (parameterized inserts, explicit UTC DateTime kind
   and NpgsqlDbType per column) rather than re-running pgloader. All 30 tables' row counts matched
   the source exactly (e.g. GambleLog 1924, PetJournal 559, AuditGameTrigger 174).
5. Recreated the FK_PetJournal_Pet foreign key that failed during the original run.

Result: all 57 tables now exist in the target with schema + data. Formal row-count verification
follows as its own step.
